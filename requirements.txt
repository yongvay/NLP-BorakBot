# ---------------------------------------------------------------------------
# READ THIS FIRST ON WINDOWS — enable long paths, or the install WILL fail
# ---------------------------------------------------------------------------
# torch ships its third-party licences nested about seven directories deep. Under
# the default 260-character MAX_PATH that overflows, and pip dies partway with:
#
#     OSError: [WinError 206] The filename or extension is too long
#
# The damage is silent and confusing: torch/ unpacks, torchgen/ never does, and
# every later run fails with "ModuleNotFoundError: No module named 'torchgen'",
# which says nothing about path length. Do not chase torchgen — there is a
# package by that name on PyPI and it is NOT PyTorch's. Installing it hides the
# real fault.
#
# In an ADMINISTRATOR PowerShell, once per machine, then REBOOT:
#
#     New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" `
#       -Name LongPathsEnabled -Value 1 -PropertyType DWORD -Force
#
# No admin rights? Put the venv somewhere short instead — it does not have to
# live in the repo, whose own path already costs 65 characters:
#
#     py -3.13 -m venv C:\v\borak
#     C:\v\borak\Scripts\Activate.ps1
#
# ---------------------------------------------------------------------------
# ffmpeg is NOT a pip package and is NOT installed by this file
# ---------------------------------------------------------------------------
# Whisper shells out to it to decode and resample audio. Without it, every
# transcription raises FileNotFoundError.
#
#     winget install Gyan.FFmpeg      # then reopen the terminal
#     ffmpeg -version                 # must print a version
# ---------------------------------------------------------------------------

# CUDA torch. Stage 3 serves Llama-3.2-3B, and on the CPU that costs ~70 seconds
# per reply -- demonstrable, but not usable in front of a grader. The 4-bit GPU
# path in app/inference.py answers in a few seconds instead. It is also the
# configuration the report actually measured, so this pin is what makes the
# demo match the report.
#
# The wheel is ~2.5 GB against ~120 MB for the +cpu build. That is the price of
# the card, and the only reason the +cpu build was pinned here first: in August
# Stage 1 was Whisper-only, and Whisper never needed the GPU.
#
# +cu126, NOT +cu124 -- the cu124 index stops at torch 2.6.0 and pinning it here
# would silently downgrade torch by seven minor versions. cu126 carries the exact
# version already in use, so this is a build swap and nothing else moves. The
# wheel bundles its own CUDA runtime and works on the demo laptop's 546.92 driver
# (which reports 12.3) under CUDA minor-version compatibility.
#
# NO NVIDIA CARD? These two lines are the whole difference; app/inference.py
# falls back to bfloat16 on the CPU by itself, and the sidebar says so:
#
#     --extra-index-url https://download.pytorch.org/whl/cpu
#     torch==2.13.0+cpu
--extra-index-url https://download.pytorch.org/whl/cu126
torch==2.13.0+cu126

# The 4-bit NF4 quantiser behind BitsAndBytesConfig in app/inference.py. It has
# NO CPU kernel, which is why the CPU path above is bfloat16 rather than 4-bit,
# and why this is a real runtime dependency and not a training-only one.
#
# On a 4 GB card this is the whole budget: 4-bit weights ~2.4 GB plus ~0.6 GB of
# CUDA context and KV cache. Whisper's ~1.0 GB does not also fit, so app/stt.py
# keeps it on the CPU by default. BORAKBOT_STT_GPU=1 overrides on
# a larger card.
bitsandbytes

# The reference Whisper implementation (Radford et al., 2023) — the one the
# proposal cites. Used only as a language detector; see app/stt.py.
openai-whisper==20250625

# Hosts mesolitica/malaysian-whisper-small-v3, which does all transcription.
# NOTE: this is transformers 5.x. app/stt.py depends on tokenizer.get_prompt_ids(),
# and on prompt_ids NOT echoing into the decoded output — earlier versions echoed
# them, which is why the app once carried a _strip_prompt() helper. If a Colab
# or Kaggle run resolves a different major version,
# expect the transcripts to differ from the ones behind the reported 0.349 WER.
transformers==5.15.0

# Attaches the QLoRA adapter to the base model at load time. Stage 3 serves the
# adapter rather than a merged checkpoint, so this is a runtime dependency of the
# app and not just of training. app/inference.py.
peft==0.18.1

# device_map and the sharded load path that from_pretrained uses for a 3B model.
accelerate

# The UI. st.audio_input (in-browser recording) needs >= 1.35.
streamlit==1.61.1

# Imported directly by the archived corpus scripts and the WER harness. Both also
# arrive transitively (pandas via streamlit, PyYAML via huggingface-hub), but a
# direct import deserves a direct declaration.
pandas==3.0.5
PyYAML
